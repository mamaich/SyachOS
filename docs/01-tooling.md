# Как устроен образ и чем он правится

## Устройство образа

`SyachOS-RG52Mini-V1.0.317-20260707.img.xz` → 3.8 ГБ, GPT, 9 разделов:

| # | Имя | Размер | Что |
|---|---|---|---|
| p3 | **dArkOS_Fat** | 99 МБ | **FAT32**: `Image`, `rk3562-rg52mini.dtb`, `initrd.gz`, `extlinux/` |
| p4 | system | 1.5 ГБ | ext4 |
| p5 | **vendor** | 254 МБ | ext4 — модули и прошивки |
| p1,p2 | uboot, resource | 4 МБ | |
| p6..p9 | cache, metadata, misc, userdata | | |

Имя p3 и включение `rk3562-darkos.dtsi` в ядре показывают, что порт вырос из той
же community-базы, что и наш EmuELEC-инструментарий.

**Загрузочный раздел — обычный FAT с обычными файлами**, значит ядро и DTB
меняются копированием с Windows, без перепаковки образа.

Параметры загрузки: `firmware_class.path=/vendor/lib/firmware`,
`androidboot.selinux=permissive`, `storagemedia=sd`.


## DTB: пересобирать из исходников нельзя, править поставляемый можно

Наш DTB из исходников отличается от поставляемого в трёх местах:

    + spk-ctl-gpios = <0x48 0x13 0x00>;    (добавлено в узел кодека)
    - spk-con-gpios = <0x48 0x13 0x00>;    (убрано из узла звуковой карты)
      vfront-porch: 0x14 -> 0x1f

Автор перенёс управление усилителем динамика и подправил тайминги дисплея уже
после публикации исходников. Подмена DTB потеряет эти правки.

Поэтому правильный способ что-то в DTB изменить — не собирать из дерева,
а разобрать **поставляемый** DTB через `dtc -I dtb -O dts`, внести правку
и собрать обратно. Круговой проход проверен: без изменений он даёт файл
байт в байт тот же. Так сделана добавка `spk-mute-delay-ms`, см.
[04-speaker-clicks.md](04-speaker-clicks.md).


## Проверка на живом устройстве (adb, root)

    insmod aic8800_bsp.ko    exit=0
    insmod aic8800_fdrv.ko   exit=0        <- CRC сошлись

    /sys/bus/sdio/devices/:  mmc2:390b:1  mmc2:390b:2
    /sys/class/net/:         lo  wlan0
    ieee80211 phy0: HT supp 1, VHT supp 1, HE supp 1

Подключение через штатные настройки Android:

    SSID: mamaich_5G   Frequency: 5180 MHz   Wi-Fi standard: 6
    tx bitrate: 206.5 MBit/s  40MHz HE-MCS 8   RSSI: -37 dBm

**CRC символов совпали**: модули, собранные GCC 11.3, приняты ядром, собранным
GCC 16.1. Это ожидаемо — `genksyms` считает CRC от препроцессированных
деклараций, а не от кода компилятора.


## Инструментальные грабли

* **PowerShell корёжит кавычки** в `adb shell '...'` — ломаются `2>/dev/null`,
  `|`, `$`. Надёжно: писать скрипт в файл, `adb push`, `adb shell sh`.
* **Git Bash преобразует пути устройства** (`/data/local/tmp` →
  `C:/Program Files/Git/data/...`). Для adb использовать PowerShell.
* **`/tmp` в WSL не переживает между вызовами** `wsl -d Ubuntu -- bash -s`.
  Промежуточные файлы класть на `/mnt/t` или делать всё одним вызовом.
* **Windows блокирует свежераспакованный крупный файл** (индексатор или
  антивирус): запись `dd` и `FileStream` падает с Permission denied, хотя
  чтение работает. Обход — потоковая перезапись в новый файл.
* Модули после сборки весят десятки МБ из-за отладочной информации:
  `aarch64-...-strip --strip-debug` ужимает `aic8800_fdrv.ko` с 17.5 МБ до 962 КБ.
* Большой markdown надёжнее писать напрямую, а не через shell-heredoc —
  кавычки и бэктики внутри текста рвут heredoc.
* **`adb shell` портит двоичный поток** — переводы строк превращаются в CRLF,
  1024 байта приезжают как 1034. Для чтения секторов и файлов только
  `adb exec-out`.
* **В Git Bash с `MSYS_NO_PATHCONV=1` пути для `adb push` надо давать
  по-виндовому** (`T:/Dump/...`): переменная отключает преобразование, и
  `/t/Dump/...` виндовый `adb.exe` уже не находит. А без неё Git Bash корёжит
  пути **на устройстве** (`/data/local/tmp` → `C:/Program Files/Git/...`).
  То есть: путь на устройстве — всегда с `MSYS_NO_PATHCONV=1`, путь на диске —
  всегда в виндовой форме.
* **adb-сервер на стороне Windows подвисает** и перестаёт видеть устройство,
  хотя оно загружено и enumerated (проверяется через `Get-PnpDevice … VID_2207`).
  Лечится `adb kill-server`. Дважды за сессию это выглядело как «устройство не
  загрузилось» — ложная тревога.
* **Не делать паузу через `adb shell sleep`** в циклах ожидания загрузки: при
  мёртвом adb команда возвращается мгновенно, и цикл на 30 итераций пролетает
  за секунды вместо минут. Только локальный `sleep`.
* **toybox `diff` выводит unified-формат** (`-`/`+`), а не классический
  (`<`/`>`) — проверки в скриптах писать под это.
* **`nohup … &` через `adb shell` не переживает отключения** — adb убивает
  группу процессов. Фоновые сэмплеры запускать, удерживая сессию открытой.

## Вспомогательные инструменты

Не шаги сборки, а подручные средства — пригодятся при следующей правке дерева
устройств или драйвера.

| Инструмент | Что делает |
|---|---|
| `tools/dtcmp.py` | структурное сравнение двух DTB, устойчивое к перенумерации `phandle`: сверяет пути узлов, имена свойств и значения без ссылок |
| `tools/dtcheck.py` | проверяет, что ссылки в собранном DTB указывают на нужные узлы — первое, чем стоит проверить свежесобранное дерево |
| `tools/kpatch-dts.py` | вносит в DTS платы семь отличий живого дерева от опубликованных исходников: три авторских, сделанных после публикации, и наши |
| `tools/rebuild-quiet.sh` | пересобирает модули `aic8800` с выключенным отладочным выводом (иначе драйвер сыплет в лог каждые 3 секунды) |
| `tools/diag/` | то, чем ловились фризы и проверялся микрофон: `freeze-trap.sh`, `state-sampler.sh`, `mic-test.sh` |
